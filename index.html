WebAgent — 多模态浏览器智能体与评测框架 独立设计与开发 · 2026年8月–至今

针对长程任务中的导航偏航、错误完成声明与中断恢复问题，独立设计模型无关的多模态 Chromium 智能体，将动作依据、可恢复执行与独立验收纳入统一框架。

交付与验证：项目内评测中，两个模型在相同的 36 项任务上共通过 71/72 次执行；覆盖开放网页、多域沙箱与强制中断恢复，保留失败轨迹用于诊断。

  • 分离规划与受控执行：以 Planner、Tool 与 AgentHook 协议解耦规划与工具执行，通过 Playwright/CDP 获取截图与 DOM 观察，以类型化工具和策略门控约束动作。
  • 使中断后的执行可恢复：通过有界重规划、循环检测与原子检查点控制长程执行，恢复进度及受支持的浏览器状态，并以强制中断任务验证恢复后的终态。
  • 让信息获取保留证据：通过图注定位 PDF 图表，以质量门控的 OCR/解析级联读取文档；保存可见搜索、来源与下载记录，通过轨迹约束校验核查信息获取过程。
  • 独立验收并分析失败：以独立终态断言验收任务，分开记录完成声明、动作有效性与轨迹约束；结合 DOM 和工具历史分析失败。
实现与评测说明

通过 AgentHook 扩展执行生命周期；遇到验证码或未获授权的高风险操作时停止执行。恢复检查同时核验执行进度、浏览器状态与任务终态。

固定版本与任务集覆盖 30 项开放网页任务、5 项多域沙箱任务和 1 项 60 阶段强制恢复任务；GLM 通过 36/36、Qwen 通过 35/36。结合终态断言、DOM 与动作历史，定位购物任务中的规划偏航，并识别导航历史残留的促成作用；保留失败记录，不以运行结束代替任务成功。

MeetingAgent — 多模态会议知识助手 项目负责人（主体架构与核心开发） · 2026年4月–至今

针对录音、文档、表格与图像分散且难以核验的问题，主导架构与核心开发，持续迭代资料摄取、可引用问答和跨会话记忆流程。

交付与验证：项目内评测中，小样本问答集经独立 Judge 评审，平均忠实度评分为 0.883、引用质量评分为 0.927；记忆流水线通过 22/22 项事件正确性检查，分别验证回答质量与记忆处理正确性。

  • 从异构素材到可引用回答：主导 FastAPI/React 模块化单体系统，分离摄取、检索与生成；通过持久化任务、租约回收与重试支持恢复，SSE 流式回答提供页码、幻灯片和时间戳引用。
  • 兼顾召回覆盖与上下文范围：并行执行摘要 Router 与 Funnel 原文宽召回，融合 Chroma 语义检索、SQLite FTS5/BM25 与 RRF，按文件分配候选并按需重排；以证据门控约束快速回答路径。
  • 保留记忆的来源与变化：以类型化事实、不可变修订快照和双时态查询区分事实有效时间与系统获知时间；关联来源证据与审核状态，支持历史追溯、跨会话检索及项目/任务跟踪。
  • 将功能完成与质量达标分开核验：构建检索、问答、记忆与端到端分层评测，结合排序指标、独立 Judge、引用核验和浏览器测试，分别跟踪功能完成、回答质量与响应性能。
实现与评测说明

SQLite 持久化任务保留死信记录；以质量门控的解析 API 级联和 PDF 本地回退处理异构资料。检索结合会话锚点，并按规则区分原子事实、有限综合与分析综合查询。

独立 Judge 对小样本问答集每例评审 3 次，忠实度与引用质量均采用 0–1 评分，报告重复评审的平均分；记忆检查覆盖写入、召回、最新值及来源关联。修复生成硬截断后，20 次性能请求均完成且未降级，但首字延迟仍未达到预设门槛；分别核验功能完成性、回答质量与响应性能，避免将请求完成视为全面达标。

零样本图文学习 — 复现与对照评测 独立完成核心复现，负责扩展集成 · 2026年3月

面向缺少类别训练图像的识别场景，使用 PyTorch 独立复现 Ba 等（ICCV 2015） 的文本生成分类器方法，检验类别描述能否支持未见类别识别；负责核心实现与团队扩展模块的集成，在统一协议下比较不同设计的效果。

  • 实现核心方法：从零实现全连接、卷积及联合三类预测器，由类别文本生成分类器权重或类别专属卷积滤波器，与冻结的 VGG-19 图像特征配合完成识别；遵循已见/未见类别评估协议，并记录与论文的数据及评测差异。
  • 建立可复现对照：构建 CUB/Flowers 训练与评测流程，生成四组与论文对应的结果表；通过词语敏感性分析、最近邻检索和滤波器可视化，检查文本属性与视觉响应的对应关系。
  • 验证扩展效果：调整并集成团队成员贡献的模块，完成 13 组受控实验，覆盖 3 种辅助损失、4 种 SBERT/CLIP 文本编码方案及 6 种 DenseNet-121/ResNet-50 主干配置；固定联合模型、VGG-19 和 BCE 设置时，多粒度 CLIP 方案的 CUB 未见类别 ROC-AUC 从基线 0.680 提升至 0.886。

  • 把规则落实到数据库：基于 SQL Server/Python CLI 设计 9 张表、7 个触发器和 26 个存储过程，交付支持借阅、罚款、审计与恢复规则的命令行系统。
  • 交付双端 Web 平台：基于 Flask/MySQL/Vue 2 实现 30 个 REST 接口、JWT 角色控制与前后端联调，使读者与管理员通过各自界面完成相应业务操作。

NLLB-200 中译英 — LoRA 微调 独立实现 · 2025年11月

面向资源受限环境的中译英适配任务，独立实现 NLLB-200-distilled-1.3B 的 LoRA 微调流程，以参数高效训练完成模型适配，并分离模型选择与最终测试。

  • 训练与数据控制：在注意力和前馈投影模块应用 rank-32 LoRA，显式设置源语言与目标语言；选取 60 万条 WMT19 训练对，仅在训练集执行质量过滤与精确句对去重。
  • 留出评测结果：使用独立的 2,000 对验证切片按 BLEU 选择检查点，再以未经修改的原始 WMT19 validation split（3,981 对）作为保留测试集，采用 5-beam 解码取得 24.9 sacreBLEU。

ViT Image-to-LaTeX — 数学表达式识别 独立设计与实现 · 2025年6月

针对公式图像转写为 LaTeX 的任务，独立设计并从零训练纯 Transformer 系统，在统一训练协议下比较印刷体与手写公式识别，分析训练稳定性和实际生成质量。

  • 实现端到端生成：构建不依赖 CNN 主干或语法约束的 770 万参数 ViT 编码器—Transformer 解码器，分别使用 50,000 条印刷体公式和 50,000 条手写公式从零训练。
  • 诊断并修复训练问题：定位学习率预热峰值附近的优化崩溃，通过全局范数 1.0 的梯度裁剪和 800 步 Transformer 预热计划，使两个数据集上的训练保持稳定。
  • 评估生成质量并分析差异：分别训练印刷体与手写体模型，同时评估 teacher-forcing 准确率和自回归 BLEU-4；在两个数据集各 500 个测试样本上，四束搜索分别取得 0.701、0.079 BLEU-4，通过对照分析训练指标与实际生成质量的差异，为后续优化提供依据。

CNN、BiLSTM 与 Transformer 文本分类 独立实现与实验 · 2025年5月

围绕文本分类中准确率与推理成本的权衡，独立实现 CNN、BiLSTM 与 Transformer，在四个数据集上建立统一实验流程，比较不同架构的效果与吞吐量。

  • 推导并实现模型：推导 vanilla RNN、标准 LSTM 与 peephole LSTM 的前向传播和随时间反向传播公式，分析循环、卷积与自注意力的计算复杂度，完成三类分类器的 PyTorch 实现。
  • 控制对照条件：统一使用 GloVe-300d 初始化的可训练词嵌入，在 IMDB、AG News、BBC News 与 SST-5 上评估；词表仅由训练集构建，避免测试集信息泄漏。
  • 量化准确率与推理效率：在固定随机种子 seed=42 的实验设置下比较 12 个模型—数据集组合，CNN 在四个数据集上均有最高前向吞吐量，在 IMDB、BBC News 与 SST-5 上分别取得 88.5%、97.3% 和 42.4% 的最佳或并列最佳测试准确率；基于 RTX 5090、batch=512 测量吞吐量，形成各数据集下的架构选型对照。
